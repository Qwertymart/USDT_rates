# USDT Rates gRPC Service

Микросервис на Go, предоставляющий gRPC API для получения текущего курса USDT/RUB с биржи [Grinex.io](https://grinex.io). Сервис автоматически сохраняет полученные котировки в базу данных PostgreSQL.

## Основные возможности

- **gRPC API**: Метод `GetRates` для получения актуальных цен (ask/bid).
- **Хранение данных**: Сохранение истории запросов курсов в PostgreSQL (используется UUID v7 в качестве первичного ключа и временная метка).
- **Graceful Shutdown**: Корректное завершение работы приложения с закрытием соединений к БД и остановкой gRPC сервера при получении системных сигналов (SIGTERM, SIGINT).
- **Структурированное логирование**: Использование `go.uber.org/zap` для вывода логов в формате JSON.
- **Обход защиты**: Настроенный HTTP-клиент с поддержкой `CookieJar` и пользовательского заголовка `User-Agent` для обхода систем защиты от ботов (Cloudflare/StormWall) на стороне биржи.
- **Покрытие тестами**: Ключевой функционал (бизнес-логика, gRPC хендлеры, клиент биржи) покрыт unit-тестами с использованием моков (`testify/mock`) и `httptest`.
- **Docker**: Приложение упаковано в минималистичный multi-stage Docker образ на базе Alpine (`CGO_ENABLED=0`).

## Конфигурация

Сервис может быть сконфигурирован через **переменные окружения** или **флаги командной строки**. Флаги имеют приоритет над переменными окружения.

| Переменная окружения | Флаг          | Значение по умолчанию                                         | Описание |
|----------------------|---------------|---------------------------------------------------------------|----------|
| `GRPC_PORT`          | `-port`       | `50051`                                                       | Порт для запуска gRPC сервера |
| `DB_DSN`             | `-db-dsn`     | `postgres://postgres:postgres@localhost:5432/rates?sslmode=disable` | Строка подключения к PostgreSQL |
| `EXCHANGE_URL`       | (нет флага)   | `https://grinex.io`                                           | Базовый URL API биржи |
| `LOG_LEVEL`          | (нет флага)   | `info`                                                        | Уровень логирования (`debug`, `info`, `warn`, `error`) |
| `LOG_FORMAT`         | (нет флага)   | `json`                                                        | Формат логов (`json` или `console`) |

*Примечание: Если в корне проекта присутствует файл `.env`, приложение автоматически загрузит переменные из него.*

## Запуск приложения (Docker)

Для быстрого запуска сервиса и базы данных PostgreSQL подготовлен конфигурационный файл `docker-compose.yml`.

```bash
# 1. Сборка бинарного файла приложения (согласно требованиям ТЗ)
$ make build

# 2. Запуск контейнера с PostgreSQL в фоновом режиме
$ docker-compose up -d db

# 3. Запуск приложения (миграции БД будут применены автоматически при старте)
$ docker-compose run --rm app ./app
```

## Команды Makefile

В проекте настроен `Makefile` для автоматизации рутинных задач:

- `make build` - компиляция Go приложения (результат сохраняется в директорию `bin/`).
- `make test` - запуск всех unit-тестов с включенным детектором гонок данных (`-race`).
- `make docker-build` - сборка Docker-образа приложения.
- `make run` - сборка и локальный запуск приложения (требует запущенной БД на `localhost:5432`).
- `make lint` - запуск линтера `golangci-lint` для проверки качества кода.
- `make generate` - генерация Go-кода на основе `.proto` файлов (требует установленных плагинов `protoc-gen-go` и `protoc-gen-go-grpc`).

## Тестирование

### Unit-тесты
Бизнес-логика, а также слой взаимодействия с внешним API покрыты тестами. Запуск тестов осуществляется командой:

```bash
$ make test
```

### Ручное тестирование gRPC
Для проверки работоспособности запущенного сервера вы можете использовать написанный в рамках проекта тестовый клиент на Go. Убедитесь, что сервер запущен, и выполните:

```bash
$ go run cmd/client/main.go
```

Либо используйте утилиту `grpcurl`:
```bash
$ grpcurl -plaintext -import-path ./api/proto -proto rates.proto localhost:50051 rates.v1.RatesService/GetRates
```

## Структура проекта

Проект организован в соответствии со стандартом Standard Go Project Layout:
- `api/proto/` - Protobuf определения сервиса.
- `cmd/`
  - `app/` - Точка входа в основное приложение.
  - `client/` - Тестовый gRPC клиент.
- `internal/` - Внутренний код приложения.
  - `app/` - Инициализация компонентов приложения.
  - `config/` - Загрузка конфигурации (через пакет `cleanenv`).
  - `exchange/` - HTTP клиент для работы с API биржи Grinex.
  - `grpc/` - gRPC хендлеры и регистрация сервера.
  - `logger/` - Инициализация логгера Zap.
  - `repository/` - Слой работы с базой данных (драйвер `pgx/v5` и миграции `goose`).
  - `service/` - Слой бизнес-логики.
- `migrations/` - SQL файлы миграций базы данных.
- `pkg/` - Публичный код, доступный для импорта извне (сгенерированные gRPC клиенты).
